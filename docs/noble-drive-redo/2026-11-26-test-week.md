# Noble Drive: test week with real bookings

Step: "Test week with real bookings" (station Handed over). Plan for the week after the live test and the admin walkthrough, built from main `c4eb854`. The B&G team takes real bookings through the site for seven days; every message, payment and contract is checked once a day.

## What every booking should go through

Taken from the code, so each point can be ticked per booking:

| When | What happens | Where it comes from | Check in the admin |
|---|---|---|---|
| Contract signed | Contract PDF generated, confirmation e-mail and SMS in the customer's language (de, en, fr, it, sr) | `sign-contract`, `_shared/bookingEmails.ts` (`booking-confirmation`), `_shared/sms.ts` | Verträge: signed; booking detail: e-mail in the e-mail log |
| Card payment | Payment status changes to paid by the webhook (confirmation sent from there for card bookings) | `create-booking-payment`, `payments-webhook` | Booking detail: «Bezahlt» without manual change |
| 24 h before pickup | SMS pickup reminder | `rental-reminders` (hourly), kind `pickup-reminder` | Customer receives the SMS (the admin shows only e-mails; SMS sends are in the `sms_log` table) |
| Pickup | Pickup protocol filled, status picked up | Admin booking detail | Protocol present, activity log line |
| 24 h before return | Reminder e-mail with the extension link `/extend/<token>` | `rental-reminders`, `rental-reminder` | Reminder time shown on the booking (`reminder_sent_at`) |
| Extension (if used) | Customer extends and signs on `/extend/…`, follow-up booking created | `src/pages/CustomerExtend.tsx` | Follow-up booking under the main booking, discounts from «Verlängerungs-Rabatte» |
| 3 h before return | SMS return reminder | `rental-reminders`, kind `return-reminder` | Customer receives the SMS (`sms_log`) |
| Return | Return protocol, cash payment set to paid by hand | Admin booking detail | Payment status change in the activity log |

## Daily check (10 minutes, same time every day)

1. Dashboard: every booking of the day is there, no booking stuck in «pending».
2. For each booking that day: tick the rows above that were due.
3. Aktivität: no failed sends or errors since the last check.
4. Note any problem in one line: booking number, what was expected, what happened.

The hourly reminders only run if the `rental-reminders` schedule exists (see the live test). If no reminder shows up on day 1, check that first.

## Pass

- At least 5 real bookings, at least one paid by card and one in cash, at least one with an extension if a customer asks for one.
- Every due e-mail and SMS sent, no manual fix of a payment status for card payments.
- No booking that the team had to handle outside the admin (paper, phone notes).

Problems found go into "Client feedback fixed" as one step each; Tarek can paste the list into a chat and it is recorded there.
